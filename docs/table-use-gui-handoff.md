# GUI 세션 인계 · 표 유형 추정

GUI 결과 보기에서 표별 이미지와 원본 쪽 이미지에 데이터 표, 도식·배치형, 혼합형, 검토 필요 중 하나를 ‘표 유형(추정)’으로 표시한다. 추정값은 원본 표 IR의 셀에서 계산한다. PNG와 JSON은 함께 제공한다. 표 분류 결과만으로 이미지 삭제나 자동 내보내기를 결정하기에는 잔여 오분류가 있다.

## 규칙과 실험 근거

기존 규칙은 행·열과 빈 셀·병합 비율이 정규적이면 흐름도와 복합 서식도 데이터 표로 판정했다. 기존 데이터 판정에만 아래 단서를 적용했다.

| 개발 자료에서 발견한 원인 | 건수 | 추가 단서 |
|---|---:|---|
| 단계 연결 또는 일정 | 4 | 독립 화살표 셀, 반복되는 사용자 정의 기호, 단계 설명 속 아래쪽 화살표 |
| 설명·정책 조항을 포함한 표 | 2 | 좁은 2열 격자 안에 긴 설명 셀이 여러 개 있음 |
| 서명 영역이 포함된 입력 서식 | 2 | 작고 빈칸이 많은 서식에서 서명·날인 표현 확인 |
| 사진과 설명을 배열한 표 | 1 | 여러 셀에 사진 캡션 표현이 등장 |

| 단위 | 개발 HWP 12개 · 106표 | 별도 HWP 8개 · 191표 |
|---|---:|---:|
| 도식·배치형 → 데이터 | 3 → 0 | 2 → 2 |
| 혼합형 → 데이터 | 6 → 0 | 10 → 7 |
| 정상 데이터 표를 데이터로 판정 | 34/44 → 34/44 | 53/66 → 53/66 |
| 정상 데이터 표 보류 | 2/44 → 2/44 | 9/66 → 9/66 |
| 전체 유형 정답 | 54 → 63 | 84 → 85 |
| 전체 보류 | 25 → 25 | 80 → 80 |

새 문서는 시드 20261129로 기업마당 공고 HWP에서 뽑았다. 기존 실험 문서를 제외하고 개선 규칙을 고정한 뒤 채점했다. 예측을 보지 않은 모델 평가자들이 표별 PNG와 IR을 보고 문서를 나누어 라벨링했다. 표마다 한 평가자가 판정했다. 개발셋에서 잡은 9건은 같은 자료로 규칙을 설계한 결과다. 새 문서의 위험 오분류 감소는 12건에서 9건(25%)이다. 정상 데이터 66개 중 기존에 보류한 9개와 다른 유형으로 보낸 4개는 개선 과제로 남는다.

## GUI 통합 계약

엔진 함수는 `govparse.table_use.classify(table)`이며 D, V, M, ?를 반환한다. 입력은 원본 셀과 문단이 있는 표 IR이다. 결과 보기 워커가 번들에 들어 있는 IR의 표 ID와 결과 이미지를 연결하고 Windows와 Qt 화면에 한글 추정값을 표시한다. 원본 문서, 실험용 PNG, 모델 가중치의 배포는 필요하지 않다.

GUI 세션은 원격 브랜치 `feature/table-use-review`에서 변경을 가져올 수 있다. 주요 파일은 `src/govparse/table_use.py`, `govparse-desktop/gpdesk/desktop_worker.py`, `govparse-desktop/Desktop.cs`, `govparse-desktop/gpqt/app.py`다. 재확인 시 JSON+PNG를 내보내고 결과를 다시 열어 표별 PNG와 원본 쪽 결과의 한글 표시, 일반 그림의 기존 표시, 예전 번들의 열기를 확인한다. 유형 추정의 후속 실험은 남아 있는 도식형 2개와 혼합형 7개를 대상으로 한다.

새 문서에서 판정이 바뀐 3개는 모두 혼합형이었다. 한 개는 혼합형으로 정확히 판정했고 두 개는 도식·배치형으로 분류했다. 세 경우 모두 데이터 표로만 내보낼 때의 정보 손실을 피하는 데 도움이 되지만 정확한 세부 유형 개선은 1건이다.
